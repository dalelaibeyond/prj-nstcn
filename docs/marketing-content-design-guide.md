# 网页营销内容设计指南

适用项目：当前 `goal-run/` 英文官网。更新日期：2026-10-04。

目标：把现有审阅版的占位内容替换为真实、清晰、能够带来询盘的网页内容。先准备事实和定位，再规划页面，逐页写文案，最后回填网站并验收。

你可以用中文整理资料和讨论；网页正式文案默认用英文。若要改变目标市场或网站语言，先在定位阶段确定。

## 1. 三个已安装 skills 怎么分工

| Skill | 解决的问题 | 什么时候调用 | 主要产出 |
| --- | --- | --- | --- |
| [product-marketing](../.agents/skills/product-marketing/SKILL.md) | 我们是谁、卖什么、卖给谁、客户为什么选择我们 | 最先调用；产品、客户或定位改变时再更新 | `.agents/product-marketing.md`，供其他营销 skills 共享 |
| [content-strategy](../.agents/skills/content-strategy/SKILL.md) | 应该做哪些内容、优先做什么、怎样回答客户问题 | 定位有初稿后；重点用于场景、FAQ、Insights 和内容优先级 | 页面内容计划、内容主题、选题与关联关系 |
| [copywriting](../.agents/skills/copywriting/SKILL.md) | 每一页的标题、正文、按钮应该怎么写 | 页面目标和事实资料确定后，逐页调用 | 页面文案、标题与 CTA 备选、选择理由、SEO 标题和描述 |

在对话里明确写“使用 product-marketing skill”等即可。下文提供可直接复制的提示词。

这些 skills 提到的 `copy-editing`、`seo-audit`、`site-architecture` 等，本项目目前没有安装。现阶段可要求 Codex 做普通文案审阅、页面规划和实现检查；不要把未安装的 skill 当作必需步骤。

## 2. 开始前：先准备最小资料包

不用一次准备齐所有材料。先用一份中文笔记回答下面八项，就能开始定位工作；不了解的地方写“待确认”。建议保存为 `docs/marketing-inputs.md`，由你填写或让 Codex 根据你提供的资料整理。

```text
1. 公司与品牌：真实公司名、品牌名；我们是制造商、方案商、贸易商，还是组合？
2. 产品：现在实际可以交付什么？哪条产品线最优先？哪些只是规划？
3. 客户：主要卖给哪个国家/地区、哪个行业、什么岗位的人？
4. 需求：客户买这些产品，要完成什么事情？最担心什么？
5. 优势：客户选择我们的具体理由，分别有什么证据？
6. 服务边界：现货、样品、品牌定制、硬件开发、软件适配分别能做到什么？
7. 转化目标：希望客户浏览后询价、讨论定制需求，还是申请样品？
8. 沟通偏好：英文还是其他语言？语气如何？对外邮箱和 WhatsApp 是什么？
```

当前网站展示 AI Toys、AI Office Assistants、AI Glasses 三条产品线，以及教育、办公、可穿戴场景。它们来自占位数据，不能直接当成你的真实经营范围。先确认保留、替换或暂不展示哪些内容。

### 随后逐步补齐的材料

| 资料 | 你需要提供什么 | 用于哪些页面 |
| --- | --- | --- |
| 公司身份 | 法定名称、品牌、成立时间、地址、真实业务角色、团队能力；自有工厂与合作工厂分清 | 首页、About、页脚、联系与法律页面 |
| 产品资料 | 型号、功能、规格、限制、照片、演示、说明书、资料表；已量产与研发中分清 | Products、详情、Comparison |
| 商务条件 | 样品安排、起订量、周期、定制条件、报价所需信息；固定承诺与按项目协商分清 | Custom、FAQ、Contact |
| 客户需求 | 常见采购问题、销售沟通原话、顾虑、使用场景；可提供脱敏记录 | 定位、Solutions、FAQ、Insights |
| 差异化证据 | 可验证的开发能力、支持范围、交付记录、测试结果及其适用条件 | 首页、产品、About |
| 案例 | 客户背景、问题、方案、实际交付、结果、统计口径，以及公开授权 | Case Studies、首页背书 |
| 认证材料 | 对应型号、适用市场、文件类型、状态、持有人、日期和可核对文件 | Compliance、产品页 |
| 品牌素材 | Logo、产品实拍、团队与制造场景图片、视频、图片描述及授权记录 | 全站 |
| 联系与数据处理 | 对外联系方式、回复安排、询盘邮件由谁处理、保存多久、隐私联系渠道 | Contact、Privacy、Terms |
| 竞品参考（可选） | 2–3 个链接，以及你希望学习或避免的具体内容 | 定位、页面规划、选题 |

建议按主题放在 `docs/marketing-inputs/`，原始产品资料、授权文件也可以保留在你已有的位置，用路径或链接引用。不要把 SMTP 密码放进营销资料。

### 给每个重要声明保留依据

准备一个简单的事实表，可放在 `docs/marketing-facts.md`：

| 编号 | 事实或声明 | 适用产品/市场 | 依据与日期 | 状态 | 可公开范围 |
| --- | --- | --- | --- | --- | --- |
| F001 | 待填写真实事实 | 待填写 | 文件路径或记录 | 已确认 / 待确认 / 不公开 | 可公开文字或需匿名处理 |

优先记录容易写错的内容：公司角色、功能、性能数字、交付周期、认证、客户成果。未知信息在内部草稿中标记 `[NEED: 所缺资料]`，写稿时不能补成事实；正式页面应补齐或调整、移除对应内容。

## 3. Step 1：建立产品与客户定位

**调用：product-marketing。** 输入最小资料包，以及现有网站和规范。当前尚未建立 `.agents/product-marketing.md`，因此这一步会形成第一版共享背景。

该 skill 可以从代码库起草，也可以逐项访谈。此项目已有较多占位内容，建议让它结合真实资料起草，并明确区分已知事实和待确认内容。

复制使用：

```text
请使用 product-marketing skill，建立本项目的产品营销背景。
先读取 docs/marketing-inputs.md、我提供的真实资料、docs/spec.md 和当前网站内容。
现有 Acme Devices、产品线、案例、数字和认证状态属于审阅占位内容，不能作为真实事实。
请先列出已有事实和关键缺口，优先确认业务角色、目标客户、主推产品、差异化和询盘目标。
每轮集中讨论一个主题，利用已有信息，避免重复询问。
用中文讨论，明确英文网页的目标市场与品牌语气。
给出定位初稿供我校正，然后按 skill 的流程保存到 .agents/product-marketing.md。
保留版本号、更新时间和 Changelog；暂不修改网站。
```

你需要确认：一句话介绍、主要客户、采购动机、核心优势及证据、服务边界、客户顾虑、品牌语气、主要转化动作。B2B 项目还应区分采购、技术评估者和最终决策者关注的问题。

**本步完成标准：** 你能明确说出“我们为哪类客户提供什么产品或服务，解决什么问题，为什么值得联系”。关键缺口已标记，其他 skills 可以读取共享背景。

## 4. Step 2：确定页面任务和内容优先级

**调用：content-strategy。** 让它从客户采购问题出发，规划内容主题、FAQ 与 Insights，并结合现有站点提出页面内容计划。详细导航或模板调整属于后续实现工作。

推荐浏览路径：

```text
首页 → 产品 / 解决方案 → 定制 / 案例 / 认证 → 联系表单
Insights → 相关产品 / 解决方案 → 联系表单
```

复制使用：

```text
请使用 content-strategy skill，先读取 .agents/product-marketing.md 和真实资料。
基于 goal-run 当前页面，制定以有效询盘为目标的内容计划。
列出各页面的目标客户、需要回答的问题、主要 CTA、所需证据、关联页面和优先级。
指出应该保留、合并、暂缓或补充的内容，并解释原因；现有规范作为参考。
为 FAQ 整理真实采购问题，为 Insights 提出 3–5 个内容主题和第一批优先选题。
关键词先标为候选；没有数据时不要编造搜索量或排名。
保存为 docs/marketing-content-plan.md，暂不修改网站。
```

### 当前页面分别需要准备什么

| 页面 | 需要回答的问题 | 主要材料 |
| --- | --- | --- |
| Home | 你提供什么？适合谁？为什么值得继续看？ | 定位、主推产品、优势证据、真实演示、询盘入口 |
| Products / 详情 | 产品能做什么？适用范围与限制是什么？ | 功能、型号、规格、照片、场景、资料表 |
| Comparison | 哪个产品适合我的需求？ | 相同口径的对比维度、适用场景、真实参数 |
| Solutions / 详情 | 在我的业务场景中，产品如何使用？ | 场景、痛点、使用流程、相关产品、限制与实施条件 |
| Custom | 哪些可以定制？合作如何开始？ | 定制范围、项目流程、客户需提供的信息、边界与交付条件 |
| Case Studies / 详情 | 有没有实际项目，结果如何？ | 背景、问题、方案、实施范围、结果依据与授权 |
| About | 公司是什么角色？团队有哪些能力？ | 真实身份、团队、合作方式、历史与实拍素材 |
| FAQ | 采购前常见顾虑如何解决？ | 样品、起订量、周期、定制、支持、认证的真实答案 |
| Contact | 我应提交什么？提交后会发生什么？ | 联系方式、五字段提示、回复安排、成功与失败文案 |
| Compliance | 什么产品有哪些可核实文件？ | 型号、市场、文件、状态和持有人 |
| Insights / 详情 | 能否帮助我理解产品、选型或采购？ | 真实客户问题、专业知识、资料来源、产品关联 |
| Privacy / Terms | 询盘数据和网站使用如何处理？ | 真实业务与数据处理流程、主体和联系方式 |

优先完成：首页、主推产品详情、定制、联系、About、采购 FAQ。产品事实应先整理，即使文案从首页开始写。案例有可公开证据时再写；资料不足时制定补充或调整方案，不用占位数字填满页面。Insights 可以后续逐篇完善。

**本步完成标准：** 每一页都有明确用途、材料需求、主要 CTA 和优先级；你知道先做哪些页面，以及哪些内容暂时缺证据。

## 5. Step 3：先试写首页，确定全站表达方式

**调用：copywriting。** 首页先用来确定品牌表达；不要一轮生成全部页面。建议先选定首屏标题、主 CTA 和关键模块，再写完整首页。

复制使用：

```text
请使用 copywriting skill，先读取 .agents/product-marketing.md、
docs/marketing-content-plan.md 和真实产品资料，为首页写英文文案。
以有效询盘为目标，内容按现有首页模块组织；需要调整模块时单独说明。
先给出 3 个首屏标题方向、简短副标题和 CTA，并用中文说明选择理由。
随后给出推荐版本的完整首页：产品入口、场景、定制能力、可信证据、最终 CTA。
每个重要声明标注内部事实依据，缺失信息用 [NEED: ...] 标记。
语言具体、自然，避免空泛行业口号和虚构成果。
包含 SEO title、meta description 和媒体需求。
保存到 docs/marketing-copy/home.md，暂不回填网站。
```

审阅时检查：首屏是否讲清产品和客户价值；“制造商”“自研”等说法是否符合真实角色；优势能否拿出证据；按钮是否对应明确下一步；英文读起来是否符合目标客户表达习惯。

**本步完成标准：** 首页方向得到确认，形成可复用的语气、核心介绍和 CTA 用词。若定位变化，先用 product-marketing 更新共享背景及版本记录。

## 6. Step 4：逐页完成文案

**调用：copywriting，每次处理一页或同类型的少量页面。** 使用相同的页面简报，避免不同页面出现互相矛盾的承诺。

### 每页简报模板

```text
页面名称与路径：
目标读者与采购阶段：
访客进入页面时想解决的问题：
本页一句核心信息：
唯一主要 CTA 与目标位置：
可用产品事实与资料路径：
证据、图片、视频或下载文件：
需要处理的顾虑：
不可承诺的内容与待确认项：
关联页面：
```

通用调用提示词：

```text
请使用 copywriting skill，为【页面名称】写英文网页文案。
读取共享营销背景、内容计划、已确认首页，以及下面的页面简报和资料。
输出 H1、简介、分节标题与正文、主 CTA、必要的辅助链接、SEO title 和 meta description。
给出标题和 CTA 的 2–3 个备选，用中文解释关键选择。
事实与限制保持一致，缺证据处标记 [NEED: ...]。
附图片/视频需求及英文 alt 文本建议。
将面向客户的文案与内部理由、事实来源、待办分开。
保存到 docs/marketing-copy/【页面文件名】.md，暂不修改网站。

页面简报与资料：
【粘贴简报、事实和资料路径】
```

建议顺序：主推产品详情 → 产品列表与对比 → 定制 → 解决方案 → About → FAQ 与 Contact → 有证据的案例 → 认证页面 → Insights。

### 不同页面的写作要点

- 产品页：把功能与客户用途联系起来，同时给出真实限制；未交付的功能不能写成现成能力。
- 场景页：描述适用对象、使用步骤和实施条件；设想场景不能包装成客户案例。
- 定制页：写清可改什么、客户提供什么、如何评估需求。起订量、周期和回复时限以实际安排为准。
- 案例页：按“挑战 → 方案 → 实施 → 结果”写；数字注明口径与时间，客户名称、Logo、引述依授权处理。
- 认证页：按实际产品与文件整理，避免把某型号或合作方的文件扩大成全公司、全产品背书。
- 联系页：现有表单为姓名、公司、电话/WhatsApp、邮箱、留言五个必填字段。可优化标签与需求提示，改变字段则需同步实现与校验。
- Insights：先用 content-strategy 选题，再要求按已确认提纲撰写文章；营销入口和 CTA 可交给 copywriting。技术内容需核对原始资料。
- Privacy / Terms：先根据真实数据处理方式起草，再由合适人员审阅。营销 skill 不能确认法律适用性。

**本步完成标准：** 优先页面已形成可回填版本；待确认声明有清单和处理方案；页面之间的产品名称、服务范围和 CTA 一致。

## 7. Step 5：做一次全站内容审阅

先检查事实，再检查结构、清晰度、语言、标题与 SEO。这属于普通审阅任务；当前没有安装 copy-editing，无需依赖它才能继续。

复制使用：

```text
请审阅 docs/marketing-copy/ 下的网页文案，结合营销背景、内容计划和事实依据。
检查公司角色、产品功能、规格、认证、案例和商务承诺是否真实且一致。
检查各页主 CTA 是否清楚，是否存在重复、术语不统一、空泛口号和 AI 式表达。
检查标题、描述、正文和图片建议是否匹配。
按“必须修改 / 需要确认 / 可优化”列出问题，注明文件和具体建议。
直接修正文案中明确的表达问题，事实不明处保留缺口，不自行补造。
保存审阅记录到 docs/marketing-content-review.md；暂不回填网站。
```

你最终确认的重点：公开身份和联系方式、主推产品、承诺范围、授权素材、案例结果、认证依据。内部批注和 `[NEED: ...]` 应在发布前处理完。

## 8. Step 6：把确认的内容回填网站

这一步是开发实现任务，营销 skills 的工作成果作为输入。不要直接修改 `dist/` 或 `.astro/`。

| 内容 | 当前对应位置 |
| --- | --- |
| 公司身份、导航、首页、按钮、页脚、FAQ、表单、法律正文 | `goal-run/src/content/site.json` |
| 产品、对比参数、产品素材、资料表 | `goal-run/src/content/products.json` |
| 场景与关联产品 | `goal-run/src/content/solutions.json` |
| 案例、结果与引述 | `goal-run/src/content/cases.json` |
| 认证状态与持有人 | `goal-run/src/content/certifications.json` |
| Insights 标题、简介与提纲 | `goal-run/src/content/insights.json` |
| 新模块、正文渲染或字段扩展 | `goal-run/src/content.config.ts`、`src/components/Home.astro`、`src/components/PageBody.astro` 等 |

回填前要知道当前实现的边界：

1. `Insights` 目前仅渲染提纲，完整文章需要扩展内容模型和模板。
2. 产品 `models`、`skus` 已有结构，但模板尚未展示；具体型号表需要实现。
3. `moq`、`leadTime` 当前只接受 `On request`，展示具体商务条件需要同步修改 schema 与模板。
4. 添加 PDF 下载需要让链接检查器验证静态文件；素材也应检查实际文件、授权和访问路径。
5. 新增、删除页面或产品后，应调整依赖固定数量和占位状态的测试，保留真实性保护规则。
6. SEO 文案要核对模板如何读取；独立 SEO 字段若尚不存在，需要实现，保存草稿不会自动展示。

公开邮箱在 `site.json` 中，后台收件人在 `.env` 中，二者独立。当前已验证 Gmail 发信、Hotmail 收件；网页公开显示哪个邮箱，需要你另外决定。

复制使用：

```text
请将已确认的 docs/marketing-copy/ 文案和真实资料回填到 goal-run 网站。
先检查目标字段与模板，直接实现已有结构能够支持的内容。
对全文文章、型号表或新增模块，同步扩展模型、模板和必要检查。
保留 ID、关联关系、授权要求和真实性保护；只在事实核实后修改占位标记。
不要修改 .env 中的邮件凭据，也不要编辑生成目录。
完成后运行适当检查，启动预览，说明已实现内容、待确认项及验证结果。
```

**本步完成标准：** 页面显示的是已确认版本，链接、素材、表单提示和移动端阅读正常；无法展示的内容已实现或明确暂缓。
